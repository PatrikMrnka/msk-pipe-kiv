## [0.2.0] - 2026-10-27

### Added
- Geometry check of the bones in step `labelmap` (`labelmap.bones.topology`): through-holes in thin bone (genus above the anatomy, e.g. iliac wing holes in MRI; the obturator foramen is kept) are filled from the other tool's segmentation of the same bone (MuscleMap hip bone), else by plate patches; gaps in long bones are bridged before the opening so the component filter keeps the whole bone; fibula shorter than 85 % of the tibia is reported. `02_labelmap/defects.json` + `patches.nii.gz`, per-structure `topology` in `labelmap.json`, `defects` metrics; `on_unfixed: fail` stops the run.
- Step `mesh` reports bone surfaces whose genus exceeds the anatomy, step `export_mw2` muscles whose mesh Muscle Wrapping cannot use (`defects.json` in each step folder).
- `mskpipe qc RUN [--show] [--png]`: list of defects (exit code 2 if one is not repaired), interactive VTK view focused on each defect, one image per defect. GUI: warning after the run and *Geometry check…* with the 3D view.
- GUI: *View…* next to the input volume opens its axial, coronal and sagittal slices (`mskpipe.gui.slice_viewer`): linked crosshair, radiological convention, physical aspect from the voxel spacing, window/level presets (auto, full range, CT soft tissue, CT bone) and right-drag, voxel index of the file, RAS position and value. The volume is read in the background in its stored type (no float copy) and freed when the window closes; 4D and oblique volumes are noted.
- Label maps in the slice viewer (`mskpipe.gui.slice_labels`): *Segmentation…* after a run (and *Open run…* in the viewer) shows the input image with the unified label map; the raw segmentations of `01_segment` and the defect repairs (`patches.nii.gz`) can be chosen, and *Add label map…* takes any integer NIfTI, also on another grid (nearest voxel by world position, nothing resampled in memory). Filled or outlines, opacity, L = on/off; list of structures with colour, volume [ml] and a check box each (All / None / Bones / Muscles), double click = crosshair on the structure, a click in the image selects it; the label under the crosshair in the status line. `mskpipe view [IMAGE|RUN] [-l LABELS]...` opens the viewer without the main window.
- `tools/gt_compare.py`: pipeline outputs vs ground truth described by a GT map (`paper/experiments/gt/*.yaml`; LHDL, TLEM 2.0 CT/MRI): surface distances, Dice, volume ratio and missing muscle ends per structure, centroid and point distances per attachment area; CSV/JSON per dataset, `--resume`. Batch `paper/experiments/e18_gt.yaml`.
- `tools/attachment_checks.py`: attachment-area checks on LHDL - the atlas of one side mirrored to the other (`mirror-atlas`, `gt-bones`, `pair`; batch `paper/experiments/e19_mirror.yaml`) and areas built as in TLEM 2.0 from the dissection fibres (`fibre-hull`).
- Value checks at two levels. Errors: bounds and validators of the schema (values that are impossible or make a step fail). Warnings: every numeric setting has a recommended range (`json_schema_extra` `recommended`, also in plugin parameters), and `mskpipe.config.sanity` reports values outside it, settings that are probably not meant (fast TotalSegmentator model, repair off, opening larger than closing + 2 mm, `PositionOnFibreQuadraticSpline`, ...), this computer (threads vs cores, saving workers vs RAM, run folder writable, free disk space, a requested GPU without NVIDIA driver) and the input (in-plane spacing outside 0.3-2 mm, slices > 3 mm, closing/opening radius below one voxel, modality given vs detected).
- `mskpipe config check [--config] [--set] [--image --modality]` prints these checks; the pre-run checks of `mskpipe run`, `mskpipe batch --dry-run` and the GUI include them. GUI: values outside the recommended range are marked amber with the reason in the tooltip and listed below the form; every numeric tooltip names its recommended range; `mskpipe config init` writes the ranges into the comments.
- Step `export_mw2` warns when the motion leaves the coordinate range of the model or has more than 1000 frames; `mskpipe batch` warns about `repeat` above 10.
- Unknown config keys and muscle names suggest the closest valid one ("did you mean ...?").
- GUI: a grey line under every setting shows its default, the allowed values and the recommended range (e.g. `Default 40 · allowed 0 to 500 · recommended 10 to 100`; what an empty value means, e.g. `empty = all cores`); it turns amber with the field when the value is outside the recommended range.

### Changed
- `segmentation.bones` chooses the source of all bones: `totalsegmentator` (pelvis, sacrum, femur; tibia and fibula from `appendicular_bones`, licence key) or `musclemap` (all bones incl. sacrum, MuscleMap label 6160; no key, TotalSegmentator is not run when the muscles come from MuscleMap too). `segmentation.tibia_fibula` was removed: a value agreeing with `bones` is ignored (0.1.0 configs stay valid), mixed sources are an error. *Use MuscleMap instead* in the setup window sets `segmentation.bones = musclemap`.
- Runs of 0.1.0 are recomputed from step `labelmap` on (step versions `labelmap` 3, `mesh` 3). With the bone repair alone (v2) the LHDL CT label map was unchanged (0 voxels differ).
- Step `labelmap` (v3): the genus of a bone is counted on its Flying Edges surface (the surface step `mesh` builds), not on the 26-connected voxels. Voxels touching only along an edge or a corner no longer count as closing a hole, so a hole reported as fixed is closed in the mesh too (TLEM 2.0 MRI: pelvis surface genus 1 + 1 instead of 4 + 2). `mskpipe.labelmap.topology.surface_topology`.
- Step `mesh` (v3) is where surfaces are guaranteed: every structure is checked as the next steps need it (bones closed, manifold, outward for pystaple; muscles in addition one part with genus 0 for Muscle Wrapping) and repaired there (mesh-level fixes, then remeshing with topology-preserving decimation, muscles also with openings and closings; `mskpipe.geometry.checked`). `meshes.json` per structure: `valid`, `problems`, `check`, `repair`, `decimation`; metrics `repaired`, `invalid`; `defects.json` lists repaired and invalid bones, located at their open edges. Surfaces that pass are the BP meshes, unchanged.
- The muscle repair moved from step `export_mw2` to step `mesh`: `export.repair`, `export.repair_max_opening_mm`, `export.repair_max_closing_mm`, `export.repair_max_volume_change` are now `mesh.repair.enabled`, `.max_opening_mm`, `.max_closing_mm`, `.max_volume_change` (old keys are still read, e.g. by `--resume` of 0.1.0 runs). `export_mw2` only verifies the mesh and copies the repair record into `export.json`; it no longer reads the label map.
- New `mesh.on_invalid` (`fail` default, `warn`): a bone that is still invalid after the repair stops the run after step `mesh` instead of failing later in pystaple.
- `attachments.params.nonrigid = cpd` is documented as for comparison only (help, GUI): its areas drift along the bone and were the least accurate on LHDL and with the atlas of the other side; `coherent_icp` stays the default.
- `labelmap.{bones,muscles}.min_voxels` became `min_volume_ml` (default 2 ml bones, 1 ml muscles), independent of the voxel size; old configs are converted with 1 voxel = 1 mm³ (the BP grid).
- `attachments.atlas` was removed (it was never read; the atlas is `attachments.params.atlas_dir` or the installed one); old configs still load.
- `export.muscles` and `export.exclude` accept only muscles of the unified label scheme (a typo was silently ignored).
- `segmentation.{totalsegmentator,musclemap}.extra_args` reject options msk-pipe sets itself (input, output, task, device, fast, ROI subset, resampling, saving workers, licence; for MuscleMap all its current options); `-ns` in `extra_args` no longer overrides `nr_thr_saving`.
- `attachments.params.nonrigid_points` must not exceed `n_points` for `coherent_icp`/`cpd` (it was cut silently); `attachments.params.seed` and `runtime.seed` are 0 to 2³²-1.
- Tighter hard bounds: `runtime.threads` ≤ 1024, `musclemap.overlap` ≤ 99, closing/opening radius ≤ 10 mm, `target_reduction` ≤ 0.99, `skeleton.body_mass` ≥ 10 kg, `cpd_w` ≤ 0.9, `cpd_sigma_init_mm` ≤ 100; `subject_id` and `skeleton.model_name` cannot be Windows device names (CON, NUL, COM1, ...).
- The attachment atlas (index readable, RAS mm, outline files present) is checked before the run, not when step `attachments` starts; an atlas without muscles of `skeleton.side` is a warning.

### Fixed
- Step `skeleton` failed in pystaple ("inertia properties are for hole-free triangulations") on the TLEM 2.0 MRI pelvis: quadric decimation left it open. Step `mesh` repairs such a bone, and `skeleton` stops with the bone name and its problems if it gets an invalid one.
- Step `labelmap`: a donor part (MuscleMap) that would close a wing hole together with the obturator foramen was dropped, leaving the hole unfilled and unreported (TLEM 2.0 MRI left hip); it is now cut to the wing hole. A bone whose genus stays above the anatomy always gets an unfixed defect.
- The genus check of step `mesh` skipped bones with an open component; open components are now a `surface` defect too, centred on the affected part for `mskpipe qc --show`.
- `orient` made a mesh of several parts outward as a whole; every part is now oriented outward on its own.
- `--set segmentation.musclemap.model_version=1.4` failed (YAML reads 1.4 as a number).

## [0.1.0] - 2026-10-21

### Added
- Project skeleton: pixi environments (`default`, `cpu`, `gpu`, `dev-cpu`), `mskpipe` CLI, CI on Windows.
- Step `mesh`: label map -> bone `.stl` / muscle `.obj` meshes in world coordinates (NIfTI RAS+, mm), Python VTK port of the BP `mask_to_mesh` (identical meshes with VTK 9.4.2), `meshes.json` index and per-structure metrics.
- `mskpipe.io` (NIfTI label maps, `labels.json` label table, STL/OBJ), `mskpipe.geometry` (surface extraction, mesh metrics, surface distances).
- Config `mesh.{bones,muscles}.min_component_fraction`.
- Step `labelmap`: raw tool segmentations (`01_segment/segmentation.json`) -> one cleaned uint8 label map (`labelmap.nii.gz`, `labels.json`, `labelmap.json` with per-structure metrics). Tool labels are mapped by name through `config/unified_labels.yaml`; TotalSegmentator `appendicular_bones` tibia/fibula are split by side; only the `skeleton.side` leg and the pelvis are built.
- Mask cleaning in mm (closing -> 3D hole filling -> opening -> components), growth only into background, one label per voxel (bones win over muscles). Validation against BP: `tools/labelmap_compare.py`, reference test `tests/steps/test_labelmap_reference.py`.
- Step `segment`: TotalSegmentator (`total`/`total_mr` by modality, `--roi_subset`, optional `appendicular_bones[_mr]`) and MuscleMap whole-body model (pinned 1.4) write raw multi-label images on the input grid plus `segmentation.json`; label maps are read from the tools (TotalSegmentator NIfTI extension, MuscleMap model JSON), never hard-coded. Both legs are segmented, so the step is reused for either side. Metrics: input grid, per-tool time and device, voxels per requested label, missing/empty labels.
- Cancellation of running tools (`ctx.cancel`): the tool and all its child processes are terminated, the step and run are recorded as `interrupted`.
- Skeleton: the STAPLE tibia body geometry is tibia + fibula of the same leg (BP convention, `skeleton.include_fibula`, merged mesh in `04_skeleton/bodies/`).
- `tools/skeleton_compare.py` (`mskpipe.validation.skeleton.compare_anatomical`): compare models built from different bones in the pelvis ACS (joint centres in mm, frame rotations in deg, markers, QC); `skeleton_parity.py` stays the same-bones parity check.
- `tools/segment_compare.py` (`mskpipe.validation.segment`): reference-free checks of the raw segmentations (all configured structures present, right of left in RAS, pelvis > femur > tibia superiorly) and comparison with reference masks (Dice, volume ratio, centroid shift, ASSD, HD95).
- Config `segmentation.musclemap.overlap` (90 as BP), `segmentation.musclemap.chunk_size`.
- Step `attachments`, plugin `atlas_registration`: atlas bones registered onto the subject's bones (symmetric trimmed similarity ICP, point-to-point start + point-to-plane refinement) followed by a selectable non-rigid stage `nonrigid`: `coherent_icp` (default; non-rigid ICP with Gaussian motion-coherence regularisation and point-to-plane correspondences), `cpd` (Coherent Point Drift, Myronenko & Song 2010), `fast_rnrr` (Fast-RNRR, Yao et al. 2020; external executable supplied by the user, not distributed) or `none`. Attachment outlines transferred with their point order, snapped onto the bone and written in the Muscle Wrapping 2.x VTK layout; `attachments.json` index with per-bone registration residuals. Atlas via `attachments.params.atlas_dir` or `MSKPIPE_ATLAS_DIR` (not distributed).
- Sacrum as a separate bone (`sacrum`, label 8 = TotalSegmentator `sacrum` + `vertebrae_S1` in `total`; `total_mr` has no S1 label, labels a task lacks are left out of `--roi_subset`): segmented, cleaned and meshed like the other bones, not used by STAPLE (`pelvis_no_sacrum` only); step `attachments` registers `pelvis_with_sacrum` (hip bones + sacrum) so sacral attachment areas (gluteus maximus, piriformis) land on bone.
- `tools/attachments_compare.py` (run vs. reference outlines), `tools/slicer_view.py` (show a run in 3D Slicer).
- Step `export_mw2`: input folder for Muscle Wrapping 2.x (`06_mw2_input/`: `setup_MuscleGeneratorTool.xml`, model copy, `.mot`, `Geometry/<body>.obj`, `muscles/<m>/<Stem>.obj|_Ori.vtk|_Ins.vtk`, `export.json`). Files in mm with `scale_factors 0.001`, world RAS frame. Rest pose = pose of the image (all bodies on the ground frame): coordinate defaults and first motion row; joints that cannot reach it (STAPLE 1-DOF knee) get their child frame rotated (`export.align_child_frames`), the residual is reported. Motion: swept coordinate (default `hip_flexion_<s>`) from the rest pose to `export.motion.end_deg`. Pelvis geometry includes the sacrum (`export.pelvis_with_sacrum`), tibia includes the fibula.
- Pre-flight checks of every muscle as Muscle Wrapping needs it: closed 2-manifold, one component, genus 0, no degenerate triangles; attachment outlines are measured after projection onto the muscle (collapse, crossing, overlap, gap) and reported as warnings only (`outline_warnings`), they never exclude a muscle. Muscles excluded by default (`export.exclude`): piriformis, obturator internus, obturator externus and tensor fasciae latae; their insertion is reached through an unsegmented tendon or fascia running around a bony pulley or down to the tibia, so it cannot be placed on the segmented belly (reason per muscle in `export.json`, `excluded_by_config`). Repair (`export.repair`): mesh-level fixes, then remeshing of the mask with topology-preserving decimation: openings 1-3 mm (`export.repair_max_opening_mm`; cut thin bridges such as a muscle sheet left next to a bone after bone subtraction, the cause of genus 2 of the LHDL iliacus), closings (`export.repair_max_closing_mm`; fill tunnels), then both; a candidate is accepted only if `check_surface` passes and the volume changes by at most `export.repair_max_volume_change` (5 %); otherwise the best attempt is reported and the muscle excluded. Failing muscles are excluded or kept (`export.on_invalid`). Metrics: exclusions and reasons, repairs (change in mm), joint residuals, rest-pose displacement, tendon gap per outline, fibre ends nearer to another bone than their attachment body (Luca2018).
- `mskpipe.geometry.kinematics` (forward kinematics of `CustomJoint` models, image pose; checked against OpenSim 4.6), `mskpipe.geometry.topology`, `mskpipe.geometry.outline`, `mskpipe.io.mw2`; `.osim` reader also reads `SpatialTransform` axes and coordinate defaults; `mask_to_surface(decimation="topology")`.
- `mskpipe.geometry.frames`, `mskpipe.geometry.attachment_guard`; config `export.inflate_radius_mm` (5.0). Step `export_mw2` replaces an attachment outline whose projection onto the muscle is degenerate (fewer than 3 distinct points or a span below two mean edge lengths; Muscle Wrapping would cut an empty patch and crash) by the outline of a small patch of the muscle surface (`areas.<kind>.inflated` in `export.json`, warning `<muscle> <origin|insertion>: area inflated`); the muscle is kept. Metrics `inflated`, `times_s`, `coordinates_space`.
- `mskpipe run IMAGE -m ct|mri [-s] [-c] [--set k=v] [-d cpu|gpu|auto] [-o RUNS] [--no-cache] [--from/--until STEP] [--resume RUN] [--json]`: the whole pipeline up to the Muscle Wrapping 2.x input; exit codes 0 completed, 1 step failed, 2 invalid request/config/device, 130 cancelled. Replaces `tools/run_steps.py`.
- `mskpipe config init [PATH] | show [-c] [--set] [--json] | schema [-o]`.
- `mskpipe.api`: interface shared by the CLI, batch runs and the GUI (`RunRequest`, `prepare_run`, `preflight`, `run`, `RunEvent`, `RunSummary`, `summarize`, `finalize_stale`); runner callback `on_start`.
- Pre-run checks (`api.preflight`, plugin hook `Plugin.preflight`): NIfTI header (3D, qform/sform present, suspicious 1 x 1 x 1 mm spacing), plugin dependencies, TotalSegmentator licence key for `appendicular_bones`, attachment atlas and Fast-RNRR executable; errors stop `mskpipe run` before the segmentation (`--no-preflight` to override).
- `mskpipe batch FILE [--dry-run] [--stop-on-error] [-d] [--set] [-o RUNS] [--no-cache] [--out DIR] [--json]` (`mskpipe.batch`): several inputs and configurations run one after another from a YAML (`experiment`, `repeat`, `defaults`, `jobs` with `matrix` = cartesian product of config values) or CSV file; repeats are the outer loop; all runs are checked (config, input, pre-run checks) before the first starts; one GPU detection per device; a failing run does not stop the batch (`--stop-on-error`), cancelling does. `<runs_dir>/batches/<time>_<experiment>/batch.json` (rewritten after every run) and `summary.csv`. Example experiment files in `paper/experiments/`.
- `mskpipe stats [PATHS] [-o DIR] [-e EXPERIMENT]` (`mskpipe.stats`): CSV tables for the paper from run folders, folders of runs and batch folders: `runs.csv` (environment, versions, device, settings differing from the defaults, times, peak RAM, exported/excluded muscles, inflated areas), `steps.csv`, `tools.csv`, `muscles.csv`, `areas.csv`, `registration.csv` and `summary.csv` (mean, SD, min, max of the wall time per experiment/job/variant/device and step; only steps executed in the run). GPU memory is not reported.
- GUI (`mskpipe gui`, `mskpipe-gui`, `pixi run -e gpu gui`; PySide6 in every pixi environment, feature `gui`): input volume with header summary and checks, CT/MRI, subject, device with detection, output folder, last step; settings form built from the config JSON Schema (one tab per section, nested groups, changed values in bold, validation with the failing field marked, `attachments.params` from the selected plugin's schema; load/save YAML; last settings remembered); pre-run checks with confirmation; progress per step with times, log, cancel, run folder and `06_mw2_input` buttons. The pipeline runs as a child process (`python -m mskpipe run ... --events jsonl --cancel-on-stdin`), so the measured resources belong to the run and a crash of a native library does not close the window; a cancel that does not finish within 30 s kills the whole process tree and finalises the manifest (`api.finalize_stale`).
- `mskpipe run --events jsonl` (one `RunEvent` JSON object per line on stdout) and `--cancel-on-stdin` (cancel on a `cancel` line or end of input).
- `api.check_image`, `api.describe_image` (shape, spacing, orientation from the NIfTI header).
- Modality `auto` (`mskpipe run -m auto`, GUI default; `mskpipe.io.modality`): Modality of the dcm2niix JSON sidecar, else MR timing (`TE=`/`TR=`) in the header description, else intensities (CT = air at or below -500 HU and a minimum below -900; MRI = no negative values); the decision and its reason are logged. An undecided volume stops the run with a request to choose CT or MRI.
- Explanations of every setting with an example (`config/help.yaml`); the GUI shows them in a popup when hovering the '?' next to a setting (sections and groups: tooltip of the tab or group box). A test keeps them complete for the config schema and the built-in plugins.
- GUI: one check-box list 'Exported muscles' (muscles of the label scheme; unchecked = `export.exclude`, `export.muscles` stays `all`; a loaded config with an explicit `export.muscles` list shows the other muscles unchecked; exclusion reasons as tooltips).

- `mskpipe setup status | weights | licence | atlas` (`mskpipe.resources`): per-user data folder (`MSKPIPE_HOME`, default `%LOCALAPPDATA%\msk-pipe`); report of what a run needs besides the code (TotalSegmentator weights per task and licence key, MuscleMap model, attachment atlas; exit code 1 if something is missing); download of the weights the configuration needs in advance (TotalSegmentator `totalseg_download_weights`, MuscleMap's own Zenodo download of the pinned model); licence key stored with TotalSegmentator's `totalseg_set_license` (format checked first); atlas installed from a folder, zip or URL (optional SHA-256, zip-slip safe) into `<home>/atlas/lhdl`.
- `mskpipe setup gpu [--remove] [--wheel-dir DIR] [--force] [--keep-downloads]` (`mskpipe.resources.gpu`): GPU support for the Windows release on demand. The pixi `cpu` and `gpu` environments differ only in the torch/torchvision builds, so the CUDA wheels pinned in `pixi.lock` (URL + SHA-256 in `gpu_wheels.json`, kept in sync by `tools/gpu_wheels.py` and a test) are downloaded, checked and unpacked into `<MSKPIPE_HOME>/gpu/<tag>/site-packages` (shared by all versions). Only child processes of a run on `cuda` and the torch probe get it first on `PYTHONPATH`; the manifest records `device.torch_overlay` and the overlay's torch/torchvision versions. `mskpipe setup status` shows it.
- GUI setup window (`Setup…`, `mskpipe.gui.setup_dialog`): data folder, TotalSegmentator licence key (format checked, stored with `mskpipe setup licence`; or "Use MuscleMap instead" = `segmentation.tibia_fibula=musclemap` in the form), attachment atlas (install from zip), model weights (present / downloaded on the first run, "Download now") and GPU support (install with progress, remove). Every action runs as a child `mskpipe setup ...` process (output in the window's log, cancel kills the process tree). Opens at start when a run with the current settings would stop on a missing licence key or atlas (can be turned off); the device line links to it when only GPU support is missing; the pre-run check dialog points to it.
- Windows release (`packaging/`, `.github/workflows/release.yml`): tag `vX.Y.Z` -> `msk-pipe-<version>-win64.zip` on GitHub Releases. The pixi `cpu` environment packed with pixi-pack (pinned 0.7.11, SHA-256 checked); packages that are not wheels (mskpipe, MuscleMap, pystaple from git, `acvl_utils` sdist) are built into wheels and injected. Launcher `msk-pipe.cmd` (GUI) / `mskpipe.cmd` (CLI): first start unpacks the environment next to it (again after the folder is moved), checks the 260-character path limit, sets the bundled atlas (`MSKPIPE_ATLAS_DIR`) and isolates the environment from the user's Python. Release folder: licences of every bundled package (`licenses/`, `packaging/collect_licenses.py`), attachment atlas `atlas/lhdl` with its own licence (CC BY-NC-SA 2.0 BE; separate asset `msk-pipe-atlas-lhdl-v1.zip` made by `packaging/make_atlas_zip.py`, pinned by SHA-256), `SHA256SUMS.txt`. The package is tested on a clean Windows runner (first start, CLI, imports, `mm_segment`, GUI import, skeleton parity, moved folder) before publishing; `workflow_dispatch` builds and tests without publishing. Windows Sandbox checklist in `packaging/sandbox/`; Zenodo metadata `.zenodo.json`.
- Model weights are downloaded before a run starts (`api.prefetch_weights`, every `mskpipe run`, batch run and GUI run that executes `segment`): missing TotalSegmentator/MuscleMap weights of the configuration and modality are fetched under the setup lock before the first step, so a first run's step times do not include downloading (timings for the paper); the time is logged separately. Offline: the run stops at once with a clear message (`mskpipe setup weights` while online); cancelling during the download stops the child process (exit code 130, batch entry `interrupted`). Unit tests never download (`conftest.py`).
- Windows Sandbox with a persistent cache (`packaging/sandbox/msk-pipe-cached.wsb`, `prepare_cache.ps1 -FromHost`): GPU support, model weights and the licence key mapped from the host, for repeated tests without downloading again.
- Setup lock between msk-pipe processes (`mskpipe.resources.lock`, OS file lock in `<MSKPIPE_HOME>/locks`, released by the OS also when the holder crashes): `mskpipe setup weights|licence|atlas|gpu` hold it and exit with code 3 (`EXIT_BUSY`, naming the holder) when another GUI window or console holds it; the `segment` step holds it while a tool downloads missing model weights (first run) and waits for another holder (cancellable), so two runs or a run and `setup weights` never write the same weight files.
- GPU support in use: removing or reinstalling it renames the overlay first and stops with "GPU support is in use" when Windows refuses (DLLs loaded by a GPU run), instead of deleting it half.
- Config `segmentation.totalsegmentator.nr_thr_saving` (default `auto`): number of TotalSegmentator export worker processes (`--nr_thr_saving`) from RAM + page file and device (1-6; TotalSegmentator's default 6 only with enough memory). Each worker loads PyTorch; with the CUDA build six of them exhausted the commit memory of a 16 GB Windows machine (Windows Sandbox: WinError 1455 "the paging file is too small", then MemoryError). Does not change the segmentation; the choice is logged.
- Release: Visual C++ runtime DLLs (`vcruntime140*.dll` from the environment's `vc14_runtime`) next to `bin/pixi-unpack.exe`, which needs them before the environment exists; a clean Windows (Windows Sandbox) reported a missing `VCRUNTIME140.dll` at the first start.
- `mskpipe/build_info.json` (written into the release wheel): msk-pipe commit and commits of git packages, used by the manifest and the skeleton parity check when `direct_url.json` and a git checkout are missing.
- MuscleMap model kept in a per-user store (`<home>/weights/musclemap`) and linked into environments that lack it (hard link, else copy), so a new release or the GPU environment does not download it again.
- `mskpipe setup fast-rnrr --accept-research-licence [--remove] [--force] [--keep-build-files] [-j N]` and *Setup… → Fast-RNRR* in the GUI (`mskpipe.resources.fast_rnrr`): Fast-RNRR (research use only, not distributed) is built on the user's computer after an explicit confirmation. The pinned source files of the authors' repository (commit `9c6e336`), OpenMesh 9.1 (C++ library of the `openmesh` sdist on PyPI), Eigen 3.4.0 and the Zig 0.13 C/C++ compiler (`ziglang` wheel on PyPI) are downloaded with SHA-256 checks (`fast_rnrr_build.json`, written by `tools/fast_rnrr_pins.py`); no Visual Studio or CMake is needed. The authors' source is compiled unchanged with their flags (`-O3 -std=c++14`) plus a serial `omp.h` (Zig has no OpenMP runtime); all OpenMesh sources are linked in directly so that its file readers are registered. The new program must reproduce the authors' test result (`data/test`, max deviation <= 1e-4 of the size; 4e-7 measured) before it is installed into `<MSKPIPE_HOME>/fast_rnrr/<commit>/` with `build.json` (sources, compiler, check, consent) and `NOTICE.txt`. The executable is found after `fast_rnrr_exe` and `MSKPIPE_FAST_RNRR`, before `PATH`; `setup status` and the GUI report it, the GUI opens Setup when `nonrigid = fast_rnrr` and it is missing; registration metrics record the build (`nonrigid_info.build`). Manual CI job *Fast-RNRR build on Windows* (workflow_dispatch, nothing uploaded).

### Changed
- GUI, attachments tab: only the parameters of the selected non-rigid stage are shown (`coherent_*` for `coherent_icp`, `cpd_*` for `cpd`, `fast_rnrr_*` for `fast_rnrr`, `nonrigid_points` for both point-based stages). Plugins mark such parameters with `show_if` in their schema; hidden values are kept and saved.

### Fixed
- Resource sampling thread died with a traceback in the run log when Windows ran out of commit memory (`OSError: [WinError 1455]` from psutil while listing child processes, Windows Sandbox during TotalSegmentator `total`); the rest of the step had no resource metrics. A failed sample is now skipped, counted in `resources.failed_samples` and reported once as a warning.
- Fast-RNRR returned NaN for the whole mesh (seen for a pelvis on Windows) when a mesh had non-manifold edges or vertices: OpenMesh re-linked such triangles on duplicated vertices and the solver read uninitialised memory. Both meshes are now made readable for OpenMesh first (`prepare_mesh`: degenerate, duplicate and non-manifold-edge triangles removed, non-manifold vertices split; fixes in `nonrigid_info.mesh_fixes`), and a non-finite result is a clear `FastRnrrError`.
- Download progress of TotalSegmentator/MuscleMap (tqdm bars, one log line per redraw: ~190 lines per model) is thinned out to one line per 10 % in the run log, `mskpipe setup weights` and the setup window (`ProgressFilter`).
- A run could hang forever when writing the output of a tool to `logs/<step>.log` failed (Windows Sandbox low on memory during TotalSegmentator `total` on the GPU: `OSError: [Errno 22] Invalid argument` on flush): the reader thread ended, nobody read the tool's stdout any more and the tool blocked on the full pipe. The output is now always read to the end (`OutputPump`); failed log writes are counted and reported as a warning of the step.
- GUI setup window: closing it during a download and opening it again created a new window in which another download could be started, while the first one kept running (several `python` processes downloading the same files). There is now one setup window for the life of the main window; closing it (Close, Esc, X) keeps a running task in the background and reopening shows its progress; only one task runs at a time; setup tasks are refused during a pipeline run and the run is refused during a setup task; quitting the GUI asks before cancelling a running download.

- `ci.yml` in the repository root (the CI workflow is `.github/workflows/ci.yml`).
- `tools/run_steps.py` (use `mskpipe run`).

### Fixed (vs. BP pipeline)
- BP `VotingBinaryIterativeHoleFilling` grew masks instead of filling cavities; BP binarization was correct only for uint8 masks; BP cleaned masks could overlap (e.g. femur/hip).
- MuscleMap exits with code 0 on errors and stores labels with the input header (8-bit inputs scale label IDs lossily): the output is checked and 8-bit inputs get a float32 copy.
